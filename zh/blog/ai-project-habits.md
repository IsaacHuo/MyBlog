# 跟 AI 做项目的几个习惯

用 AI 写代码一年多，我留住了三个习惯，分别用在动手之前、方案成形之后和每次会话收尾。AI 最容易浪费时间的，恰恰是这三段。

## 动手前先让 AI 去找现成的

我每次开始一个新项目，第一件事是让 AI 先去 GitHub 找现成的方案，然后才考虑写代码。

我给它的是下面这段提示词。

```
我要做一个 XXX。
先不要写代码。去 GitHub 找能直接使用或二次开发的开源项目，确认是否还在维护、部署是否麻烦、哪些功能可以复用。
最后告诉我应该直接用、基于现有项目改，还是自己开发，并给出最简单的 MVP 方案。
等我确认后再动手。
```

就这么一段，每次做项目都先让 AI 找答案，我再动手。大多数需求网上都有现成或半成品，闭着眼从零写，等于重复造轮子。让 AI 把维护状态、部署成本和可复用范围先查一遍，给出直接用、改造还是自研的判断，我再拍板。调研这一步交出去，省下的时间很可观。

## 方案成形以后再让它挑刺

第二个习惯来自 grill-me 这个 Skill。我把它当成评审工具用，专门检查已经成形的计划和方案，找出遗漏的边界情况。交互设计、架构设计和程序设计里，它都派得上用场。

我一般不在一开始就 grill。做产品设计时，先把需求、目标和已经想好的交互逻辑描述给 Agent，让它先做一版 Mock UI。我常用 Claude，这方面的效果相对好一些。拿到原型以后继续聊几轮，把一眼就能看出问题、自己也清楚怎么改的地方先处理掉。等整个方案基本成形，才开始 grill-me。

原因在于，自己设计交互时最容易想到的是那条正常路径，用户按照预期理解产品，按预期顺序操作，设备正常，网络正常，也没做什么意料之外的事。真实用户不会永远这样用。不同的人理解方式、操作习惯和注意力不同，设备、网络、权限、数据状态也可能完全不同，边界情况一开始很难想全。

你可以把 grill-me 理解成一次产品评审会。你已经拿出一个相对完整的方案，团队其他人开始不断提问。用户这样操作怎么办，这个状态有没有考虑，为什么一定要这样设计，前一步没有完成呢，网络中断呢，两个状态同时出现怎么办。这些问题未必都会改变方案，但它们会逼你重新检查那些默认成立、却从没认真验证过的假设。

技术设计和程序设计也一样。程序员能想到多少异常路径、边界条件和潜在风险，很大程度靠经验。很多技术方案主流程没问题，真正容易出问题的地方藏在失败路径、状态切换、并发、重试、兼容性和各种极端情况里。所以技术场景下，grill-me 很像一次技术方案评审，让另一个成员站在不同角度提问，再根据问题去完善设计。

grill 过程中会冒出很多问题，不是每个都值得花时间。有些场景发生概率极低，有些即使发生影响也很小，剩下的大多是过度设计，直接跳过。重点是把那些自己原本没意识到、又确实重要的问题找出来。

也不一定非要装这个 Skill。完全可以把思路写进 CLAUDE.md 或 AGENTS.md，当方案已经形成时，从另一个视角主动提问，检查遗漏的边界情况、隐含假设和潜在风险。grill-me 给我的最大启发是，AI 不只可以帮我们生成方案，也能成为那个专门挑问题、做 Review 的人。

## 把状态写下来，别让它每次重新理解

第三个习惯是给 AI 留日志和状态文件，减少它反复理解项目。

AI 编程工具每个新会话都是从空白上下文开始的，它不记得上次聊了什么。项目隔几天再做，重新开一个会话，AI 要重新读一遍代码、重新理解一遍背景，才能回到原来的位置。来回几轮，时间都耗在让它理解上。

解决办法是把 AI 需要知道的背景和进度写下来，放进项目里。现在主流 AI 编程工具都约定读项目里的规则文件，比如 CLAUDE.md 或 AGENTS.md。这个格式像给 AI 看的 README，写清楚项目怎么构建、怎么测试、有哪些约定。新会话一打开，工具先读这些文件，起点就不再是零。这格式已经很普及，GitHub 上六万多个开源仓库在用，Codex、Claude Code、Cursor、Copilot 这些工具都支持。

为什么不能全堆在对话里？Anthropic 讲上下文工程的文章里提过一个现象叫 context rot，上下文窗口里的 token 越多，模型能准确回忆出来的反而越少。上下文是有限资源，越用越稀薄。官方文档还建议，规则文件超过两百行就拆成按路径加载的小文件，只在碰到相关代码时才读，免得占满上下文。

另一个做法是进度文件。项目跨度大时，可以维护一个 NOTES.md 或类似的进度文档，记录已经做了什么、踩过哪些坑、下一步是什么。每个会话结束前让 AI 把当前状态更新进去，下次会话直接读这份文件，接着上次的位置继续，不用重新解释。Claude Code 里就有类似的自动记忆机制，会话结束时它自己把学到的东西写成笔记，下次自动读回来。

把三个习惯放在一起看，它们是同一条线的三段。先让 AI 找现成方案，省的是重复造轮子的功夫。等方案成形再让它挑刺，把没想清楚的地方提前暴露。至于状态文件，它让每次重新开始都不用从零来。跟 AI 合作久了，我觉得它更像一个会忘事的同事，替它把记忆管好，比催它快更管用。
